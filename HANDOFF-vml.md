## Root causes of "draws nothing", fixed in vml.js

1. `document.namespaces.add("v", URN, "#default#VML")`, the three-argument form, binds the behavior as each node is made, and IE 6 then drops every property set by script.
   That explains the white fill, no path, and coordsize 200,100 sitting beside the default 1000,1000.
   The fix is the two-argument form plus one behavior rule per tag (v:shape, v:fill, v:stroke).
   Probes: shots/p1.png to p5.png.
2. A v:group measures what it holds, not its width and height (221x81 for a 200x100 group), and does not clip.
   The fix: the svg is a span (relative, inline-block, overflow hidden, W x H), and a g is a plain span; points are baked through the CTM anyway.
   Probe: shots/b1.png.
3. VML's stroke defaults are a round join and cap; v:stroke now carries SVG's defaults (miter join, miterlimit 4, flat cap).
4. Static VML draws only after the page finishes loading.
   This is why the hold page can never show static VML, though script-made VML still draws there.
   It doesn't affect cdom.

The Chrome stand-in (tools/cdp.mjs IE6_OLD) now models these cases.
It lists the following in `__vml.bad`, which tools/legacy.mjs wants empty:
- a v: node made before the namespace;
- a v: tag with no behavior rule;
- any v:group.

And after a namespaces.add with an implementation, a node keeps IE's defaults.
tools/legacy.mjs checks the exact setup, the svg span's size, clipping and the stroke defaults.

## Task 2: the LaTeX app's "This command is not supported." in IE 6

The root cause is measured in IE 6, but not yet reproduced on the LaTeX build itself.
IE 5 to 8 refuse an input's type once the input has ever had a parent, even after it is taken out again: setAttribute throws "This command is not supported."
The exception is setting it to the type it already has.
cdom's shim appends an opened element to its parent at once.
latex/src/page.c:1219 does `cd_el_id("input", "filter")` then `cd_attr("type", "search")`, inside a parent, so it throws.
- A lone input takes any type, and an unknown one ("search") stays text.
- `el.mergeAttributes(loneInput, false)` carries the type onto a parented input.
- A button's type is never refused; IE 6 ignores it, and its default is already "button".

Probe pages: /Users/alex/VMs/ie6-xp/vmlprobe/type.html and type2.html; results in shots/type6.png and type6b.png.
legacy.c never hit this, because its file input is top-level and has no parent when its type is set.
